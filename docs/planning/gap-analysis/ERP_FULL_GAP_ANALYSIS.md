# 1. الحكم العام

## 1.1 التصنيف الدقيق

> **النظام الحالي = ERP-L3.2** على مقياس من 5 مستويات.
> **ERP "متكامل بكل ما تعنيه الكلمة" = L4.5 على الأقل.**
> المسافة بينهما: **304 فجوة** موثَّقة أدناه، منها **23 حرجة** و**105 جوهرية**.

## 1.2 لماذا ليس متكاملاً — السبب الجذري

**السبب ليس نقص الجهد — بل نقص النطاق المعلن.** الوثيقة `SCOPE_AND_NON_GOALS.md` تُعلن 11 "غير هدف" صريح، أهمها:

| غير الهدف المعلن | الأثر على "التكامل" |
|---|---|
| عمليات HR التشغيلية | ❌ لا يوجد نظام HR |
| العمليات العميقة للقطاعات | ❌ أغلفة تجارية فقط |
| السوق/الإضافات الطرفية | ❌ لا بيئة تطوير |
| AI ومساعد محادثة | ❌ لا أتمتة ذكية |

بالإضافة إلى **5 مجالات لم تُذكر كغير أهداف لكنها غائبة تماماً**: MRP · WMS متعدد المستويات · CMMS · إدارة المشاريع · التجارة الخارجية.

# 2. الفجوات الحرجة

> **معيار "حرجة": تمنع البيع في سوق مستهدف، أو تُفقد النظام صفة "ERP"، أو تخلق خطراً قانونياً/محاسبياً.**

## 🔴 H-01 · الفوترة الإلكترونية السعودية (ZATCA) غير عاملة
| البند | التفصيل |
|---|---|
| **الحالة** | `apps/api/src/modules/tax/adapters/zatca/zatca-stub.ts` — دالة واحدة تُعيد `{status: "FAILED"}` دائماً |
| **السبب** | 4 بوابات تحقّق غير مستوفاة: GATE-1 مواصفات رسمية · GATE-2 sandbox · GATE-3 تحقّق نماذج · GATE-4 مراجعة قانونية |
| **الأثر** | **السعودية = أكبر سوق GCC. لا يمكن بيع النظام لأي منشأة سعودية قانونياً.** |
| **ما ينقص تحديداً** | ① توليد QR بصيغة TLV-base64 (المرحلة 1 — **لا يحتاج API خارجي**) ② حقل ICV (Invoice Counter Value) تسلسلي ③ حلقة hash (invoice hash chain) ④ توليد UBL 2.1 XML ⑤ إرسال + استلام clearance/reporting ⑥ شهادة CSID + توقيع XAdES ⑦ صفحة إعدادات الشهادة |
| **الأخطر** | **المرحلة 1 (QR) لا تحتاج أي وصول خارجي — هي مجرد ترميز رياضي. غيابها قرار لا حاجة.** |

## 🔴 H-02 · رمز QR في قوالب الطباعة **نصّ لا صورة**
```typescript
// packages/ui/print/templates.ts سطر 272
const qr = payload.qrPayload
  ? `<div ...>[QR] ${esc(payload.qrPayload)}</div>`   // ← يطبع النص "[QR] abc123" بدل رمز ممسوح
  : "";
```
**الأثر:** حتى لو تولّدت بيانات QR، الفاتورة المطبوعة **غير قابلة للمسح الضوئي** → غير ممتثلة في أي نظام يتطلب QR مرئي.

## 🔴 H-03 · لا يوجد تخطيط احتياجات مواد (MRP)
| ما يوجد | ما ينقص |
|---|---|
| `reorder-service.ts` — تنبيه "المخزون تحت الحد" + كمية مقترحة | **لا حساب احتياجات صافي** = (الطلب المتوقع + المحجوز + الأمان) − (المتاح + المطلوب شراؤه + تحت التصنيع) |
| لا شيء | **لا انفجار BOM متعدد المستويات للطلب** (level explosion للاحتياج) |
| لا شيء | **لا توليد تلقائي لأوامر الشراء/الإنتاج من الاحتياج** |
| لا شيء | **لا أفق تخطيط (planning horizon) ولا دورات (buckets) يومية/أسبوعية** |
| لا شيء | **لا MPS (جدول الإنتاج الرئيسي)** ولا ATP (متاح للوعد) |

**الأثر:** مصنع حقيقي يخطط يدوياً في Excel. **هذا وحده يُخرج النظام من دائرة ERP التصنيعي.**

## 🔴 H-04 · لا مسارات تشغيل ولا مراكز عمل (Routing / Work Centers)
جدول `production_orders` لا يحتوي: `routing_id` · `work_center_id` · `operation_no` · `setup_time` · `run_time` · `machine_id` · `shift_id`.
جدول `bills_of_materials` لا يحتوي: أي حقل تشغيلي.
**النتيجة:** أمر الإنتاج = "استهلك مواد → أنتج صنفاً". لا مراحل، لا توقيت، لا تكلفة تشغيل حقيقية (العمالة والتحميل معدل ثابت يدوي فقط).

## 🔴 H-05 · لا نظام موارد بشرية — "رواتب" فقط
| المجال | الجداول الموجودة | الغائب |
|---|---|---|
| الحضور والانصراف | ❌ صفر | `attendance_records` · تكامل أجهزة البصمة · الورديات |
| الإجازات | ❌ صفر | `leave_types` · `leave_balances` · `leave_requests` · الأرصدة المرحّلة |
| العمل الإضافي | ❌ صفر | `overtime_rules` · `overtime_entries` |
| التقييم | ❌ صفر | `performance_cycles` · `competencies` · `goals` |
| التوظيف | ❌ صفر | `vacancies` · `applicants` · `interviews` |
| التدريب | ❌ صفر | `training_programs` · `certifications` |
| الهيكل التنظيمي | ❌ صفر | `positions` · `job_grades` · `org_units` · `reporting_lines` |
| وثائق الموظف | ❌ صفر | `employee_documents` · تواريخ انتهاء الإقامة/الجواز |
| **ضريبة الرواتب والتأمينات** | ❌ صفر | **لا حساب GOSI (سعودي) ولا تأمينات اجتماعية ولا ضريبة دخل على الرواتب** |
| نهاية الخدمة | ⚠️ مبلغ مُدخل يدوياً | لا حساب تلقائي حسب قانون العمل |

**الأثر:** أي شركة > 20 موظفاً تحتاج نظام HR خارجياً = **ERP غير متكامل بالتعريف**.

## 🔴 H-06 · جدول المشاريع = 6 أعمدة لا أكثر
```typescript
projects = { code, name, nameAr, parentId, status }   // هذا كل شيء
```
| القدرة القياسية | الحالة |
|---|---|
| موازنة المشروع (budget vs actual) | ❌ لا موازنة مرتبطة بالمشروع (budgets.scope=PROJECTS لكن لا أعمدة مشروع في المشروع) |
| موارد المشروع وتكلفتها | ❌ صفر |
| نسبة الإنجاز / القيمة المكتسبة (EVM) | ❌ صفر |
| مهام المشروع ومراحله (WBS) | ❌ صفر — `crm_tasks` عامة غير مرتبطة بمشروع |
| أوامر التغيير (Change Orders) | ❌ صفر |
| مقاولون من الباطن ومستخلصاتهم | ❌ صفر |
| احتجاز الضمان (Retention) | ❌ صفر |
| دفعات مقدمة للمشروع | ⚠️ `contract_advances` للعقود فقط |

**الأثر:** شركة مقاولات أو استشارات = غير كافٍ إطلاقاً.

## 🔴 H-07 · لا مواقع تخزين في المخزون (No Bin/Location)
```typescript
item_stock = { itemId, warehouseId, qty, avgCost }   // لا موقع
stock_moves = { itemId, warehouseId, direction, qty, ... }  // لا موقع مصدر/هدف
```
**الغائب:** `warehouse_locations` · `zones` · `aisles` · `racks` · `bins` · `putaway_rules` · `pick_strategies` · `LPN/pallets`.
**الأثر:** مستودع > 5000 صنف أو > 500 موقع = إدارة يدوية. لا WMS.

## 🔴 H-08 · لا ائتمان مستندي للتجارة الخارجية
`letter_of_credit` = 0 · `incoterm` = 0 · `bill_of_lading` = 0 · `customs` = 1 (ذكر عابر) · `hs_code` = 0.
**الغائب:** اعتماد مستندي (LC) · تحصيل مستندي · ضمانات بنكية · بيانات جمركية · إقرار استيراد · بوليصة شحن.
**الأثر:** مستورد/مصدّر في اليمن أو الخليج = **العمليات الأساسية غير مدعومة**.

## 🔴 H-09 · لا تكامل دفع حقيقي
`SandboxProviderAdapter` هو **المحوّل الوحيد**. `DR-002` (اختيار المزوّد) مفتوح.
**الأثر:** لا يمكن تحصيل اشتراكات فعلية → **النموذج التجاري SaaS معطّل**.

## 🔴 H-10 · الأسعار كلها PLACEHOLDER
`OQ-002` مفتوح · `plans.price_amount = 0` لكل الخطط · صفحة `/pricing` تعرض شارة PLACEHOLDER.
**الأثر:** لا يمكن التسعير أو البيع.

## 🔴 H-11 · لا RFC/RFQ ولا مقارنة عروض موردين
`rfq` = 0 في كل الكود. دورة الشراء تبدأ من طلب شراء → أمر شراء مباشرة.
**الغائب:** `rfqs` · `rfq_lines` · `supplier_quotes` · `quote_comparison` · `awarding`.
**الأثر:** لا مفاوضة منظمة مع الموردين = خسارة مالية مباشرة.

## 🔴 H-12 · لا RMA (إدارة مرتجعات كعملية)
`credit_notes` موجودة (إشعار دائن مالي) لكن:
- لا `return_authorizations` ولا `RMA` workflow
- لا موافقة إرجاع، لا استلام مرتجع، لا فحص حالة، لا إعادة تخزين مبرَّرة، لا استرداد
- `rma: 166` في البحث = كلها إشارات في نصوص/تعليقات، **صفر جدول**
**الأثر:** مرتجع = إشعار دائن فقط بلا عملية لوجستية.

## 🔴 H-13 · لا دورة تحصيل (Dunning) للعملاء
`subscriptions.dunningStep` موجود **للاشتراكات فقط**. للعملاء (AR):
- لا `dunning_letters` · لا `collection_actions` · لا تصعيد تلقائي
- تنبيه `invoice.overdue` فقط (إشعار داخلي)
**الأثر:** لا أتمتة تحصيل = ديون معدومة.

## 🔴 H-14 · لا تعدد مستويات الموافقة حتى شرطياً
`approval_policies.policy jsonb` + `approval_step integer` واحد.
**الغائب:** سلاسل موافقة متعددة (مدير → مالي → CEO) · موافقات شرطية بالمبلغ/القسم · تفويض أثناء الغياب · موافقة بالبريد/الجوال.
**الأثر:** شركة > 30 موظفاً تحتاج مصفوفة صلاحيات حقيقية.

## 🔴 H-15 · لا CMMS — صيانة الأصول غائبة
`assets` لا يحوي: `maintenance_schedule` · `maintenance_orders` · `service_history` · `warranty_expiry` · `insurance_expiry` · `license_expiry` · `odometer` · `meter_reading`.
**الأثر:** إدارة أسطول/معدات = غير مدعومة.

## 🔴 H-16 · الضرائب: ضريبة القيمة المضافة فقط
| نوع الضريبة | الحالة |
|---|---|
| VAT (القيمة المضافة) | ✅ كامل — 6 معاملات + 10 ولايات |
| ضريبة الدخل على الشركات | ❌ صفر |
| ضريبة الدخل على الرواتب (PIT) | ❌ صفر |
| الاستقطاع من المنبع (WHT) | ❌ صفر |
| الضريبة الانتقائية (Excise) | ❌ صفر (مذكورة "خارج النطاق") |
| رسوم الدمغة (Stamp Duty) | ❌ صفر |
| ضريبة العقارات | ❌ صفر |
| **إقرارات غير VAT** | ❌ صفر |

## 🔴 H-17 · لا استيراد إلا 3 أنواع
`kind: z.enum(["PARTNERS", "ITEMS", "OPENING_BALANCES"])` — **هذا كل شيء**.
**الغائب:** استيراد دليل الحسابات · الأرصدة الافتتاحية للحسابات · الأصول الثابتة · الموظفين · قوائم الأسعار · العقود · الميزانيات.
**الأثر:** onboarding عميل جاد = إدخال يدوي بالملايين.

## 🔴 H-18 · مفتاح `items.import_export` غير مُمنوح لأي خطة
الشاشة موجودة، الـ API موجود، **لكن لا مستأجر يستطيع رؤيتها** (كما أثبتتُ سابقاً).

## 🔴 H-19 · لا نسخ احتياطي/استعادة متفاوتة للمستأجر
لا `tenant_backup` · لا استعادة مستأجر واحد · `data_export` مجرد تصميم.
**الأثر:** لا يمكن تلبية طلب "أعطني بياناتي" (GDPR/عقود) — رغم ادعاء العقد.

## 🔴 H-20 · لا SSO / SAML / LDAP / OAuth للمؤسسات
`oauth: 8` كلها إشارات · `api_key: 0`.
**الأثر:** عميل مؤسسي يريد Azure AD / Okta = غير ممكن.

## 🔴 H-21 · لا API عام مع مفاتيح (API Keys)
`api_key: 0` · `webhook_out: 0`.
**الأثر:** لا تكامل عميل → لا يمكن ربط النظام بأي شيء خارجي برمجياً.

## 🔴 H-22 · لا تنبيه/إشعار عبر SMS أو WhatsApp
`channel-port` يُعلن "SMS providers TBD per market". FCM فقط + بريد.
**الأثر:** في السوق العربي، WhatsApp = قناة العمل الأساسية.

## 🔴 H-23 · لا دعم للغات > العربية والإنجليزية
`locales = ["ar", "en"]` — ثابتة في الكود.
**الأثر:** الأوردو (باكستان)، الفرنسية (المغرب)، الأمهرية = غير ممكن. اليمن فيه مجتمعات.

# 24. الحكم الختامي

> **النظام اليوم = 60.0% من ERP متكامل.**
>
> **الأساس المالي (94%) من الطراز الأول — لا يُلمس.**
> **البناء الوظيفي فوقه ناقص: التصنيع 38% · HR 26% · التجارة 10% · التكاملات 22%.**
>
> **إذا كنت تبيع لشركة تجارية/خدمية صغيرة — هذا نظام ERP كامل.**
> **إذا كنت تبيع لشركة تصنيع أو > 100 موظف أو في السعودية/مصر — هذا نظام ERP ناقص بشكل جوهري.**

**أهم 5 فجوات لا يمكن التنازل عنها لأي ERP "متكامل":**

1. **MRP** — بلا تخطيط مواد، المصنع لا يعمل.
2. **HR كامل** — بلا حضور/إجازات/تأمينات، كل شركة تحتاج نظامين.
3. **ZATCA** — أكبر سوق GCC مقفل قانونياً.
4. **WMS (مواقع)** — مستودع حقيقي لا يعمل بلا أرفف.
5. **محرك سير عمل** — بلا موافقات متعددة المستويات، لا حوكمة.

**أهم 5 نقاط قوة لا تُمَس:**

1. محرك الترحيل الواحد — أساس كل شيء.
2. عزل المستأجرين على مستوى قاعدة البيانات.
3. الدقة العشرية الصارمة.
4. الصدق الهندسي الموثَّق (يقين نادر).
5. التوحيد متعدد الشركات.

## The review fix this increment carries (found BY the gate, the honest record)

**THE ORDER-DEPENDENT CAPTURE CLASSIFICATION** — the first full-suite run
(the unified head, 238 files) failed exactly one test:
`attendance.spec (b)` expected the 0081 dedupe floor's
`ATTENDANCE_DUPLICATE_PUNCH` and received `ATTENDANCE_SESSION_OVERLAP`
for a duplicate-punch candidate (the same check_in as a committed
session, open-ended, against a day holding 08:10→12:00 + 13:00→16:00).

- **Root cause (deterministic, not a flake):** the capture path
  classified the candidate in ONE pass over `listDerivationRows` — a
  query with **no ORDER BY**, so PostgreSQL's physical (heap) order
  decided which row the loop met first. A heap order that surfaced the
  13:00 sibling before the 08:10 row fired SESSION_OVERLAP before the
  exact-match row was ever reached. The T-17 suite had passed on a
  favorable heap order — same code head, different physical layout.
- **The fix (the import path's proven shape):** the classification is
  extracted as the pure domain law
  `classifyCaptureConflict` (`domain/attendance-classification.ts`) —
  the exact-match (duplicate punch) decision runs over the WHOLE day
  BEFORE any overlap comparison, so the typed code is a function of the
  day's session SET, never of the rows' physical order. The service
  throws the same two typed errors as before; the checkout path was
  already order-insensitive (a ∃-quantified boolean); the import path
  already classified exactly-match-first (its two `find`s — the fix
  mirrors it).
- **The pin:** `__tests__/attendance-classification.spec` 5/5 — the
  exact flake shape in BOTH row orders (the later-sibling-first order
  was the pre-fix SESSION_OVERLAP), the pure-overlap shape, the disjoint
  acceptances, the ABSENT-marker non-interference, and the empty day.
  The DB-side end-to-end refusals stay pinned by `attendance.spec (b)`
  (5/5 re-run) and `inv031.spec` P1's six seeded permutations.
- **Evidence:** first run (the failure, 1/3,307) · post-fix run (the
  repair proven at the same file set: 238/238 · 3,307/3,307 · 527.33s) ·
  the final run (with the OA-06 spec added: 239/239 · 3,313/3,313) — all
  three logs in [audit-evidence/phase045-t19/](../../../audit-evidence/phase045-t19/).

**The environment note (recorded, not code):** this gate round ran in a

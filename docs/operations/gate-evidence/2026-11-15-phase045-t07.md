## What landed (T-07)

- **The type catalog (HR-02):** CRUD + activate/deactivate — the code
  unique, the accrual/cap bounds typed before any write, and THE
  BR-055 LAW: a type accrues 0.00 until the tenant configures it (the
  accrual run refuses a 0-accrual type — never a fabricated statutory
  quantity; the jurisdiction regime is PHASE-046's).
- **INV-031 AT THE APPROVE BOUNDARY:** used never exceeds entitlement +
  carried-forward at ANY moment — the typed refusal (scaled-integer
  comparison) BEFORE the decrement, never a negative remaining; the
  charge lands on the START year's cell (the documented convention),
  and the decrement rides the SAME ambient transaction as the decision.
- **THE SPAN LAW:** an employee is never on two leaves at once — a new
  span overlapping a PENDING-or-APPROVED span is the typed refusal.
- **The lifecycle:** PENDING → APPROVED / REJECTED / CANCELLED — the
  0083 decided-stamps CHECK honored (only PENDING carries none — a
  CANCEL is a decision too); a decided request never re-decides (the
  typed 409); the request's days = the calendar span (end − start + 1),
  computed server-side, never caller-supplied.
- **The accrual run:** the entitlement RECOMPUTE (idempotent — never an
  increment; used stays) = accrual × months / 12 (scaled-integer
  round-half-up, the numeric round(x,2) mirror):
  - annual (monthly_grant=false): the employment months in the year (12
    for pre-year hires; the months from the hire month to December for
    mid-year joiners — the hire month counts fully, the documented
    convention; 0 for future hires; prorate_joiners=false grants the
    full window to everyone — the tenant's explicit choice);
  - monthly (monthly_grant=true): the vesting through the run's
    asOfMonth, capped by the employment months;
  - THE INV-031 PRESERVATION: a recompute that would LOWER an
    entitlement below (used − carried) is the typed ALL-OR-NOTHING
    refusal — the balance law never breaks, the cells stay.
- **The carry-over rollover:** the next year's carried_forward =
  min(remaining, cap) — the excess TRUNCATES with the audit line
  (`hr.leave_rollover` carries the truncated count + days); a 0-cap (or
  a 0 carry) writes NO cell; exactly one year forward (typed); the SET
  (idempotent), never an increment.
- **The routes:** types CRUD + activate/deactivate, the balances read
  (the remaining computed in SQL), the requests (create / approve /
  reject / cancel / list — paginated, total + hasMore), the accrual
  run, the rollover — every row `@RequirePermissions("hr.leave")` +
  ROUTE_PERMISSIONS-registered (the §8 law). The audit trail:
  `hr.leave_type_*`, `hr.leave_request_created/approved/rejected/
  cancelled`, `hr.leave_accrual_run`, `hr.leave_rollover`.

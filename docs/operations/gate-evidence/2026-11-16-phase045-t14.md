- **THE ENVELOPE LAW REPAIR (the dated 2026-11-16 finding):** T-14's
  first HTTP-level test made the family's controllers actually answer
  HTTP for the first time — and the answer was `{"data":{},"meta":…}`.
  **Every hr controller site (69 across the 10 controllers) now awaits
  its service call INSIDE `envelope(...)`.** The pre-T-14 shape
  `return envelope(this.svc.x(...))` handed Express a Promise NESTED in
  the data field: (1) JSON serialization of a pending promise is `{}`
  — every hr endpoint answered an empty payload; (2) a service
  rejection became an UNHANDLED promise AFTER a 200 was already sent —
  the error filter never saw it, so every hr error path was a silent
  200-empty. The hr routes were never exercised at the HTTP layer
  before T-14 (the `__db__` specs call the services directly), so the
  defect was invisible to every earlier gate. **The SAME latent
  pattern exists in the shipped modules' unawaited sites**
  (sales/inventory/purchasing/sourcing/wms/tax/… — e.g.
  `sales.controller.ts listQuotations`) — out of this phase's scope,
  recorded for the owner's dispatch (the parallel-work protocol: no
  cross-phase edits without the owner's direction).

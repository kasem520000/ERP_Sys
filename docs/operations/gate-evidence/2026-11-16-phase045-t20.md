## The fix — the HR shared atomicity floor

**`apps/api/src/modules/hr/infrastructure/atomic.ts`** — ONE module, the
treasury CC-02 idiom (the transaction-scoped advisory lock + the POST-LOCK
recompute), the same gate for every writer of an entity:

| Family | The gate | The writers that take it (BEFORE their guard read) |
|---|---|---|
| attendance day | `hr.attendance-day\|{employeeId}\|{workDate}` | manual capture · the import commit (every employee-day the file touches, locked before the DB floors read) · the anomaly-resolve correction · the one-shot checkout · the derivation run (the whole universe, locked before the verdict reads) |
| leave span | `hr.leave-span\|{employeeId}` | request creation · approval (the two-leaves-at-once law's BOTH doors — approve re-checks the overlap excluding its own span) |
| balance cell | `hr.balance-cell\|{employeeId}\|{leaveTypeId}\|{year}` | approval · encashment (G-51) · the accrual recompute · the carry-over rollover — **`used_days` is the source of truth** (leaves AND encashments), read UNDER the lock, never a side-sum over the requests table |
| employee link | the CONDITIONAL compare-and-set | `UPDATE employees SET user_id = … WHERE id = … AND user_id IS NULL RETURNING id` — the row lock the UPDATE takes is the gate; the second concurrent linker matches ZERO rows and renders the typed `BRIDGE_ALREADY_LINKED` naming the winner |

**Deadlock freedom by construction** (the mfg cancel/complete star argument):
within a namespace every acquirer locks the same globally-sorted key order
(the bulk arms sort + chunk at 500 keys per statement); across namespaces the
only ordered edge is approve's span→cell, and no writer takes them in
reverse — the wait-for graph is a forest. Advisory xact locks are re-entrant
within a UoW (capture's post-write derive re-takes the day key it holds) and
all release at COMMIT/ROLLBACK.

**The structural repairs that ride the floor:**

- `attendance-service.capture/checkout` — the day lock before the overlap
  read; `deriveDays` locks its whole employee-day universe then RE-READS the
  rows under the lock (the verdict never computes on a stale day; the ABSENT
  synthesis cannot land twice).
- `attendance-import-service` — split into `analyzeParsed` (parse→pair) +
  `applyDbFloors` (ALREADY_IMPORTED / SESSION_OVERLAP): the commit locks the
  file's employee-days FIRST, then runs the floors under the locks (preview
  stays lock-free — zero writes, an honest snapshot, races included); the
  resolve-IMPORT correction takes the same day lock.
- `leave-service.approve` — the span lock + the approve-boundary overlap
  re-check (excluding the request's own span) + the cell lock + **the cap
  check against the CELL's `used_days`** (the side-sum read is deleted);
  `createRequest` takes the span lock; `runAccrual` ensures + locks every
  target cell before the INV-031 preservation reads; `rollover` locks BOTH
  years' cells, re-reads the remaining under the lock, and adds the **toYear
  preservation guard** (never LOWER a cell's carried below
  `used − entitlement` — the accrual mirror).
- `leave-posting-service.encash` — the cell lock + the post-lock cell re-read
  (the remaining and the decrement are one atomic step).
- `bridge.store.linkUser` — the conditional write (above); the service
  renders the typed refusal naming the concurrent winner. The 0085
  partial-UNIQUE stays the user-side floor (23505 surfaced typed).

## The permanent two-transaction suite

**`apps/api/src/__db__/hr/hr-writer-races.spec.ts` — 16/16** (the mfg
cancel/complete race harness idiom): `vi.spyOn` splits the WINNER's UoW
exactly at the owner's window — after the winner's write arm has run inside
its transaction (every gate held, nothing committed) — then the LOSER runs as
a real service call in its OWN `withTenant` UoW on its OWN pooled connection,
and the world is classified from committed reads (`pg_locks` ungranted =
"blocked", the post-fix shape; the loser settling inside the window =
"slipped", the pre-fix shape = the owner's proof — the tests FAIL there).

over every cell, and the bridge's exactly-one-link-event / no-unlink-event.

### The honest repairs this wave (both PRE-EXISTING defects surfaced by the fresh sandbox, both proven at the base commit by a stash test, both zero-behavior-change)

1. **The payroll controller's DI shape**: the 029-era constructor params
   declared NO `@Inject()` tokens (correct in the production build via
   tsc's `emitDecoratorMetadata`), but the vitest/esbuild transform
   emits **no `design:paramtypes`** — W-4's route-level spec boots the
   controller through the real Nest pipeline under that transform and
   the params resolved `undefined` (the route 500'd). The repair: the
   **explicit `@Inject()` tokens on every param** (the identity/hr
   house pattern) — mechanical, token = the same class, zero
   production change, and the whole controller is now resolvable under
   both pipelines.
2. **`domain-core/uuidv7.ts` `randomFill`**: the parameter type
   `Uint8Array` (= `Uint8Array<ArrayBufferLike>` under TS 5.9) is not
   assignable to the stricter `getRandomValues` signature an ambient
   **@types/node 14 chain** can win in packages without a direct
   `@types/node` dependency (sync-core via the root auto-discovery
   walk). The fresh sandbox's clean turbo cache re-ran the package
   typecheck for the first time in a while — **the W-3 evidence's
   sync-core line rode a `cache hit, replaying logs`** (verbatim in
   `audit-evidence/phase046-w3/typecheck.log`), so the latent fragility
   was invisible until now. The repair: pin the parameter to
   `Uint8Array<ArrayBuffer>` — the exact type of the sole allocation
   site and the intersection of every ambient signature. Zero runtime
   change; the base-commit stash test proves the failure predates W-4.

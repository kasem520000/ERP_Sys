## What landed (T-05)

- **Migration 0087** (`attendance_import_batches` + `attendance_import_anomalies`):
  the import LOG — one row per COMMITTED import with the file's sha256
  FINGERPRINT ((tenant, sha256) UNIQUE — the same file never commits
  twice), the counts (CHECK-coherent: imported + quarantine ≤ rows),
  the MAPPING the import was interpreted with, and the file's device
  identity (an IMPORT record carries NO device_ref — the 0081 CHECK
  binds device_ref to source='DEVICE' only; the batch is the
  traceability); the QUARANTINE — every refused line with its RAW LINE
  + the typed reason, PENDING review, the resolution stamps CHECKed
  (PENDING ⟺ no stamps). Grants: the log SELECT/INSERT (append-only);
  the quarantine SELECT/INSERT/UPDATE (the resolution write); no
  DELETE for either. RLS: the house triple + the purge path.
- **The generic CSV adapter** (`attendance-import-service.ts`): the
  ZKTeco-style DEFAULT mapping (user id, timestamp, direction, device
  id — ISO timestamps, comma, header row) + the CONFIGURABLE mapping
  (tenant_settings key `hr.attendance.import.map`, the
  communication-module direct-key precedent; column indexes 0–49,
  ISO/DMY/MDY formats, comma/semicolon/tab delimiters, a direction-less
  mode). NO vendor SDK, no lock-in — the mapping is the interpretation
  contract, never a guess.
- **The pipeline** — PREVIEW is the analysis alone (ZERO writes);
  COMMIT = the same analysis + the log + the records + the quarantine:
  parse (quoted fields respected) → shape (INVALID_ROW: missing
  columns, unparseable timestamps, unrecognized directions) → horizon
  (OUT_OF_RANGE: before today−400d or after tomorrow, the tenant's tz
  — a longer backfill is a deliberate migration, not a device file) →
  the employee CODE axis (UNKNOWN_EMPLOYEE — device files name people
  by their printed code) → the in-file DEDUPE (DUPLICATE_IN_FILE: the
  same employee + timestamp collapses to ONE — the plan's law) → the
  PAIRING (per employee-day, wall-clock order: an IN opens, the next
  OUT closes; a second IN while open is DOUBLE_PUNCH_IN; an OUT with
  no open session is ORPHAN_PUNCH_OUT; a direction-less file pairs
  ALTERNATELY — the documented convention; an odd count leaves the
  last session open, the MISSING_PUNCH derivation's honest signal) →
  the DB floors (ALREADY_IMPORTED — the 0081 dedupe floor vs the DB;
  SESSION_OVERLAP — INV-031 at import time; both anchors the anomaly
  on the session's in-line with the out line noted in the detail).
- **THE TIME-SPACE LAW:** the file's timestamps are NAIVE tenant-local
  wall-clocks (device clocks carry no offsets); the ENTIRE analysis
  runs in wall-clock milliseconds and the ONLY conversion to
  timestamptz is the store's `AT TIME ZONE` at the DB boundary —
  never a float-parsed date string.
- **The review surface:** the batch log + the anomaly quarantine
  (paginated, total + hasMore) and RESOLVE — REJECT (the note is the
  verdict) or IMPORT-with-corrections (the corrected session rides the
  SAME capture laws: shape, envelope, interval, INV-031, the dedupe
  floor — typed refusals before any write, the anomaly stays PENDING
  on a refusal) with source IMPORT + the original batch's
  traceability; a resolved anomaly never resolves twice (the typed
  lifecycle conflict).
- **The routes:** the WIZARD (preview, commit, the mapping GET/PUT)
  rides `hr.attendance.import` (the 0086 seed's law — "run the
  device-import wizard"); the REVIEW (batches, anomalies, resolve)
  rides `hr.attendance` — every row `@RequirePermissions` +
  ROUTE_PERMISSIONS-registered (the §8 law). The audit trail:
  `hr.attendance_import_committed` (the counts + the fingerprint),
  `hr.attendance_import_mapping_saved`,
  `hr.attendance_anomaly_resolved` (the action + the corrected facts).
- **The derivation:** a commit derives the file's span for its
  affected employees immediately (the register never shows a stale
  verdict — the same law the derive endpoint rides).

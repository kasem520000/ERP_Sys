## Rejection UX — CONFLICT_RESOLUTION §3 (full table)

PERIOD_LOCKED→[edit-and-resend, cancel] · PRICE_CHANGED→[accept-server-price,
edit-and-resend, cancel] · INSUFFICIENT_STOCK→[edit-and-resend,
accept-partial, cancel] · CREDIT_LIMIT_EXCEEDED→[edit-and-resend,
request-approval-online, cancel] · STALE_VERSION→[review-and-merge diff,
discard] · ITEM_INACTIVE/PARTNER_INACTIVE→[cancel, substitute-and-resend] ·
VALIDATION_ERROR→[edit-and-resend] · DEVICE_REVOKED/TENANT_SUSPENDED→admin
state, no resubmission. Every choice → `local_events` row {kind:
"rejection_choice", choice, reason, trace_id, command_id, payload, at} +
resend = NEW commandId + fresh idempotencyKey (same entity id).

## Post-W3 integration fix (DR-P21-3b-1 — applied by the coordinator)

The E2E journey (T-P21-3b) crossed the seam no unit test crossed:
`enqueueDraftCommand` stored the BUSINESS payload in the outbox `payload`
column, but the engine sends `JSON.parse(row.payload)` VERBATIM on the wire —
rows without the full v2 envelope are unattributable server-side and freeze
IN_FLIGHT forever. FIX (verified green in both E2E journeys): the column now
carries the FULL envelope (`JSON.stringify(command)`); `outbox-view.tsx`
gained the compat unwrap (envelope.payload → business payload, bare-payload
rows still render); the store-client test pin updated. Follow-up fix:
`parseTypedRejection` reads `details.traceId` (the typed lastError envelope
shape) so rejection choices audit-log the rejecting response's traceId —
acceptance criterion 5 now met end-to-end (the E2E asserts it).

## Deviations / decision notes

1. **The webview twin-host architecture** (coordinator-resolved): the
   sync ENGINE never runs in the webview — the console is 100%
   bridge-driven (async repository over bridge.sql); the engine is the
   shell-side runtime (2-a's SyncDesktopHost, Node profile: E2E harness +
   chaos + Windows CI). The UI mirrors host state from store reads.
2. **DR-P21-09 (coordinator)**: the bridge contract gained the OPTIONAL
   `sync` member (syncNow/pushNow) — manual sync-now needs a bridge
   surface; Rust commands sync_sync_now/sync_push_now + the sync_driver
   seam (source-only, Windows CI compiles; fail-closed
   SYNC_DRIVER_NOT_REGISTERED) + parity-check coverage.
3. Reprint = printHtml path in the webview (ESC-POS bytes stay
   shell-runtime-side) — field parity asserted, byte parity impossible
   across the boundary (honest note).
4. enqueueDraftCommand's two-statement crash window (outbox first) —
   documented in store-client.ts.
5. The unlock screen duplicates 1-b's D-04 watermark decision against
   async reads (thin, cited).
6. Schema parity via source-file parsing instead of a devDep import
   (depcruise boundary) — the REAL DDL is still parsed (drift fails here).

## Deviations / recorded observations

1. **react-native resolved to 0.76.9** (manifest `^0.76.5`; the brief
   anticipated `0.76.5` possibly failing to resolve — `^0.76.5` resolves
   cleanly to 0.76.9, the newest 0.76.x in the registry snapshot; pure JS,
   installs + typechecks fine). `native/package.json` pins **`0.76.5` exact**
   for the EAS toolchain per the brief.
2. **vitest "root's exact version"**: the root `package.json` declares NO
   vitest devDependency — the workspace standard is `^3.2.4` (desktop, api,
   web, sync-core, contracts, ui). `@erp/mobile` uses `^3.2.4` → resolves
   **3.2.7**, the byte-identical instance every other importer resolves
   (verified across all seven packages' node_modules).
3. **Dual React-types hoist conflict (root changes beyond the brief):** with
   `@types/react@18.3.x` (mobile, RN 0.76) and `@types/react@19` (web/ui) in
   one store, pnpm's hidden hoist picked 18.3.31, flipping lucide-react's
   un-peer-declared React types and breaking `pnpm --filter @erp/ui
   typecheck` (ReactNode bigint mismatch). Fix: NEW `.npmrc`
   (`hoist-pattern[]=!@types/react`) + root devDependency pin
   `@types/react@19.3.0` (the pre-022 hoisted version) — restores the 021
   resolution state exactly; apps/mobile resolves its own 18.3.31 locally.
   Both typechecks re-verified green.
4. **RN component trees do not yet transform under vitest (honest deferral,
   feeds a DR-P22-xx):** the `react-native` package itself ships Flow syntax
   (`import typeof …` in index.js + `@flow strict-local` Library sources) that
   Node/esbuild/rollup refuse to parse (verified on 0.76.9). babel
   (`@babel/core` + `babel-plugin-syntax-hermes-parser` +
   `@babel/plugin-transform-flow-strip-types` — all already in the pnpm store
   via RN's own tree) provably produces clean output; wiring it into
   vite-node (candidate: `vite-plugin-react-native`) is the remaining
   engineering task for the screen/primitive render waves. Until then the
   in-sandbox JSX test validates the pipeline with a pure-React component —
   recorded in `__tests__/scaffold-jsx.test.tsx` + README, never a silent
   skip.
5. **Lockfile cosmetic:** vitest/vite peer-resolution tuples gained
   `terser@5.51.2` (terser entered the store via react-native → metro), same
   3.2.7/7.3.7 versions everywhere — no behavioral change.
6. **Escape-hatch granularity:** the documented disable names BOTH rules
   (`no-restricted-syntax, no-restricted-properties`); for object-key
   violations only `no-restricted-syntax` fires, so eslint emits an "Unused
   eslint-disable directive" WARNING (exit stays 0). Harmless — keep both
   names so the same protocol works for member-expression violations.
7. **eas.json comments** use `"//"` JSONC keys (tolerated by
   `@expo/json-file`) rather than `//` line comments — JSON has no comments.

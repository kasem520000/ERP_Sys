## Binding mechanics applied

1. **The two-layer mirror (DR-P22-02):** Layer 1 mirrors the canonical export
   byte-identically (the gate's comparison is mechanical — same nesting, same keys);
   Layer 2 derives RN-usable values (numbers, single fonts, shadow objects) — the root
   gate checks BOTH (canonical ⊆ mobile + the derivation table).
2. **The Flow bridge (T-P22-1a deviation 4 — SOLVED):** react-native's published source
   contains Flow syntax that esbuild cannot parse. `vitest.rn-bridge.mjs` transforms
   `node_modules/react-native` (and only it) through the RN babel preset's flow-strip
   pipeline inside the vitest module graph; `vitest.setup.rn.mjs` installs the test
   setup. Result: REAL `render()` from `@testing-library/react-native` works in-sandbox —
   primitives.test.tsx renders every primitive (11 render/create call sites). This
   unblocks 2-e/3-b screen tests (handoff below).
3. **Logical props only:** every primitive styles exclusively with logical props
   (`marginStart/End`, `paddingStart/End`, `textAlign: "start"|"end"`, `start`/`end`
   offsets); the test suite asserts NO physical-direction style key appears in any
   emitted style tree — direction-agnostic by construction (AR-RTL and EN-LTR renders
   identical at the JS-tree level).
4. **The inTokens allowlist:** `erp-ui/no-raw-design-values` governs mobile src too —
   the theme module is whitelisted (it IS the token source); all other mobile code must
   import tokens, never hard-code values (test files included — the canonical-literal
   checks live in the root gate).

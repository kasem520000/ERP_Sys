## Binding mechanics applied (MASTER-PLAN §5 + DR-P22-04)

- **AR-first catalog:** `defaultLocale = "ar"`; the product is RTL-first
  (RTL_DESIGN_RULES §1) and `en` is the mirror. Bilingual parity is enforced
  TWICE — statically via the `Dictionary` interface (`tsc` rejects any key
  drift; this typecheck IS the compile-time proof) and at runtime via
  `assertMobileParity()` executed at module load, plus the root gate.
- **The 359-key vocabulary** covers the full DR-P22-11 screen set + the
  OFFLINE_CAPABILITIES rows 13/14/29 + Journey G surface: common chrome +
  tab bar; the four post-sync states (PENDING_SYNC/POSTED/REJECTED
  (editable)/DRAFT_LOCAL) with hints; all **ten rejection codes** with label +
  detail (PERIOD_LOCKED, PRICE_CHANGED, INSUFFICIENT_STOCK,
  CREDIT_LIMIT_EXCEEDED, STALE_VERSION, ITEM_INACTIVE, PARTNER_INACTIVE,
  VALIDATION_ERROR, DEVICE_REVOKED, TENANT_SUSPENDED); the **eight-action
  table** (edit-and-resend, accept-server-price, accept-partial, cancel,
  substitute-and-resend, review-and-merge, discard, request-approval);
  parked-rejections screen; onboarding/login; device registration + trust;
  unlock (biometric + PIN fallback + lockout); home dashboard; statements;
  invoices (list/view + provisional offline numbers); route visits (tier
  pricing, balances, free goods); scanner; van-sale capture (LOCAL-VALID
  advisories for price/stock/credit-limit, serial/batch capture); collection;
  van load/unload + van stock; returns; count lines; personal home (zero
  write affordances, 256 KB note); notifications (row 29 + the FCM
  no-financial-payload note); settings (device/sync/biometric/language/
  storage/sign-out); as-of + offline/online-only affordances
  ("requires connection" — never queued); force-update; validation errors.
- **Digits policy (RTL_DESIGN_RULES §8 + ADR-0009):** amounts are TEXT
  canonical decimal strings (`/^-?\d+(\.\d+)?$/`) — malformed input returns
  VERBATIM (the formatter never invents precision); thousands "," decimal "."
  are PHYSICAL and never become "٬"/"٫" even under `arab`; the minus sign
  leads the digits; the exact decimal scale is preserved; latn is the
  default everywhere and `arab` display rides an option
  (`{ numerals: "arab" }`) that never applies to identifiers —
  `formatDocNumber` is always latn and defensively normalizes Arabic-Indic
  contamination back to ASCII. `TABULAR_NUMS_STYLE` carries
  `fontVariant: ["tabular-nums"]` for MoneyText/numeric columns (the theme
  task's rendering half).
- **Bidi (DR-P22-03 / RTL §5):** `bidiIsolate` = FSI…PDI for mixed fragments;
  `bidiIsolateStrong` = LRI…PDI for identifiers (doc numbers, IBANs, serials,
  phone numbers — LTR by definition, never mirrored); punctuation stays
  OUTSIDE the isolate (the classic «فاتورة رقم INV-0001:» corruption case);
  `sanitizeBidi` strips RLM/LRM/ALM, the embedding/override controls
  (U+202A–U+202E) and the isolates before user/server-provided content is
  re-wrapped.
- **Runtime is pure TS:** no react-native imports anywhere in `src/i18n/**`;
  `nativeDirection(locale)` returns `{locale, direction, isRTL, allowRTL:
  true, forceRTL}` — the native shell calls
  `I18nManager.allowRTL(nd.allowRTL); I18nManager.forceRTL(nd.forceRTL)` at
  boot and on language change (the port boundary, MASTER-PLAN §5).
- **`t(locale, key, params?)`:** `{param}` interpolation; a missing param
  token stays VISIBLE (`{date}`) — an honest, greppable omission; number
  params are `String()`-ed as-is (formatting is digits.ts's job, never a
  screen's).
- **Gate:** `check-mobile-i18n-parity.ts` mirrors the web gate structurally
  (flatten with array/nesting support, `parityReport`, `main(argv)`, the
  fixture-module hook for negative meta-tests, the `requireOrImport` shim,
  the argv guard) — output line `== mobile i18n parity: ar=N keys, en=N
  keys ==`, exit 1 on drift/empty.

## Deviations (numbered)

1. **`_locale` parameter naming** in `formatQty`/`formatDocNumber`: the
   digits policy makes quantity/doc-number shapes locale-invariant, but the
   brief's signatures keep the locale parameter positional — so it is named
   `_locale` (exempt from `noUnusedParameters` + `argsIgnorePattern: "^_"`)
   with a JSDoc note. Call sites still read `formatQty(locale, qty)`.
2. **The `options?: { numerals?: "latn" | "arab" }` param extends beyond
   `formatMoney`** to `formatQty` and `formatDate` — the brief spelled the
   option for formatMoney only, but MASTER-PLAN §5 binds "latn default; arab
   display behind tenant config" to the whole formatter family. Additive,
   backwards-compatible (omitted = latn).
3. **`formatDate` canonical style ignores the numerals option** (always
   `2026-11-05` in both locales): the ISO form is identifier-adjacent (like
   doc numbers) — arab display applies to short/medium/long only. Pinned by
   test + module-header doc.
4. **Currency display map covers `SAR` only; unknown ISO codes render
   verbatim in both locales** (bilingual-neutral) — callers pass ISO codes,
   never pre-localized labels; empty currency = bare amount.
5. **Language toggle values are endonyms in both locales**
   (`settingsLanguageAr` = "العربية" under ar AND en; `settingsLanguageEn` =
   "English" under both) — the universal language-picker convention; noted
   inline in the catalog.
6. **`appTitle` is a localized brand name, not a literal mirror**
   (ar "تطبيق الميدان" / en "ERP Field") — avoids a mixed-script RTL title;
   `appTagline` is fully translated.
7. **`collectMobileParityViolations` exported beyond the web pattern** (the
   web `assertDictionaryParity()` takes no args): the pure validation core
   lets tests prove drift/empty rejection without spawning the gate process;
   `assertMobileParity()` wraps it for the module-load check. The root gate
   mirrors the web script shape independently.
8. **No CI negative shell script added for the mobile gate** (the web
   `boundary:negative-i18n-test` pattern) — the script carries the same
   fixture-module hook for a future one; this wave's proof is the vitest
   negatives + the manual fixture run quoted above. Flag for 4-b (docs/
   closeout) to consider adding `boundary:negative-mobile-i18n-test`.
9. **No new dependencies, no `pnpm install`** — the brief's constraint;
   `pnpm-lock.yaml` untouched by this task.

## Handoff notes for 2-e / 3-b (screens) + 1-b (theme)

- **`t()` API:** `t(locale, key, params?)` — `key` is `keyof Dictionary`
  (autocomplete + compile-time existence); params are strings/numbers, pass
  PRE-FORMATTED values from digits.ts (never `String(number)` raw money).
  A missing param token renders literally (`{date}`) — visible, greppable.
- **The composition recipe for identifier runs (RTL §5):**
  `t(locale, "invoiceViewNumber", { number: bidiDocNumber(formatDocNumber(locale, docNo)) })`
  → `الرقم: ⁦INV-2026-0001⁩` — digits normalize to latn, the run is
  LRI-isolated, punctuation stays outside. Same for IBANs/serials/phones.
- **Money/qty/dates in screens:** `formatMoney(locale, amount, "SAR")` →
  `1,234.50 ر.س` / `1,234.50 SAR`; `formatQty` for counted/served
  quantities; `formatDate(locale, iso, "medium"|"long")` for human labels
  and `"canonical"` for as-of/ISO text; the tenant's arab display rides the
  options param. MoneyText joins `TABULAR_NUMS_STYLE` (from digits.ts — a
  plain frozen object, structurally assignable to RN TextStyle) + logical
  `textAlign: "end"` on numeric columns (RTL §8).
- **Key-naming conventions:** flat camelCase namespaced per screen/area —
  `common*`, `tab*`, `syncState*`/`sync*`, `asOf*`, `reject<Code>*`,
  `action*`, `parked*`, `login*`/`onboarding*`, `deviceReg*`, `unlock*`,
  `home*`, `statements*`, `invoice*`, `routes*`, `scanner*`, `vanSale*`,
  `collection*`, `vanLoad*`/`vanUnload*`/`vanStock*`, `returns*`, `count*`,
  `personal*`, `notifications*`, `settings*`, `err*`. New keys land in BOTH
  `ar` and `en` in the same commit, in the same section order —
  `assertMobileParity()` (module load) + `pnpm check:mobile-i18n` fail
  otherwise. Screens NEVER hardcode strings; the catalog is the single
  vocabulary source.
- **Locale plumbing:** settings toggle persists `"ar"|"en"` (SecureStore is
  2-b's port) → `resolveLocale(persisted)` (garbage/null falls back to ar);
  `otherLocale()` swaps the pair; on change call `nativeDirection(newLocale)`
  and apply via `I18nManager` in native/App.tsx, then re-flow (the
  `settingsLanguageChangeNote` string already tells users this).
- **Import surface:** screens import from `@erp/mobile` (the root barrel
  re-exports the i18n area) or relative `"../i18n"` — but NEVER import the
  root barrel from inside `src/**` (the constants leaf rule, depcruise
  no-circular). 1-b: `TABULAR_NUMS_STYLE` (digits.ts) is the value your
  MoneyText primitive should join onto text styles; the mobile tokens task
  owns the visual half (colors/fonts), this module owns the numeric policy.

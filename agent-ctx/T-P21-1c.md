## Decisions + deviations (for the completion report's DR list)

- **D1 (minisign key-id derivation)** — generated-key ids = first 8 bytes of
  SHA-512(public) (minisign proper: unkeyed BLAKE2b-8, unavailable without
  new deps). Key ids are opaque routing metadata, NEVER a verification gate
  (the Ed25519 check always decides) → no security-semantics change.
- **D2 (test/CI private key format)** — the helper produces the UNENCRYPTED
  minisign secret core (algo+keyid+seed||pub, base64; 74 bytes), not the
  scrypt-wrapped .key file — production signing stays CI-only with
  store-backed keys (S-15); documented in the module header.
- **D3 (manifest signature dual-mode — reconciles the single Tauri
  `platforms.signature` field)** — `verifyManifestSignature` accepts EITHER
  (a) mode "manifest": a REAL signature over the canonical manifest JSON
  (signature field blanked; `signManifest` is the CI/test helper — this is
  how the dual-trust rotation window is exercised), OR (b) mode "bundle":
  the stock Tauri v2 shape where the field holds the signature OF THE BUNDLE
  (required for the Rust shell updater's `latest.json`) — bound to a trusted
  key id at the manifest stage, then FULLY Ed25519-verified on the
  downloaded bundle bytes before install (client.ts, D-06 boundary). A
  manifest-signed manifest passes the manifest gate but cannot complete an
  install (tested + documented) — the D-06 install boundary always requires
  the field to verify over the bundle bytes. Bundle-URL scheme is https-only
  (enforced in the client before download).
- **D4 (blocked-min-version is terminal)** — `runUpdateCheck` returns
  `{ state: "blocked-min-version", forceUpdate: true, manifest, reason }`
  WITHOUT auto-downloading ("below-minimum app blocks — client concern",
  PHASE-021 §2.7); the blocked screen drives the mandatory install through
  the exported `downloadAndInstallUpdate` tail (the same verified path the
  happy path uses) — extra export, documented.
- **D5 (gate order quirk, documented in code)** — cohort gate precedes the
  min-version gate (binding §7 order), so a below-minimum device outside the
  cohort reports not-selected; `haltRemedy` therefore documents that
  force-update remedies publish at stagePercent 100.
- **D6 (WebView2 supported edge)** — exactly `WEBVIEW2_MINIMUM`
  (109.0.1518.78) ⇒ **supported** (the task's binding probe matrix pins it
  as "supported-edge"; the floor is the tested baseline). The degraded band
  is strictly (minimum, recommended): 110.x ⇒ degraded, 120.0.2210.61 ⇒
  supported. The §7 banding phrase "≥ minimum but < recommended ⇒ degraded"
  is disambiguated by the binding test matrix.
- **D7 (cohort math, exact integers)** — selection is
  `bucket * 100n < BigInt(stagePercent) * 2n**64n` where bucket = first 8
  bytes of sha256("deviceId:channel:version") big-endian — the plan's
  `bucket/2^64 < p/100` as an EXACT BigInt rational (zero float precision
  loss). Non-integer/negative/NaN stagePercent fails CLOSED (nobody
  selected — a broken rollout config never fans out).
- **D8 (compareSemver prerelease rule)** — a non-numeric segment sorts
  BEFORE a numeric one (1.2.3-beta < 1.2.3, semver ordering); CalVer leading
  zeros compare numerically (2026.11.04 == 2026.11.4); missing segments are
  zero (109.0 == 109.0.0.0).
- **D9 (ESC-POS documented assumptions)** — 80 mm ≈ 48 columns, 58 mm ≈ 32
  columns (12 dots/mm, font A); one code point = one column; WRAPPING ONLY,
  NEVER SHAPING (raw UTF-8 Arabic bytes go to the printer as-is — the
  Windows driver/printer owns shaping/RTL); Arabic tokens (any token
  containing an Arabic char) are unbreakable even when wider than the roll;
  Latin tokens hard-break at the width. Golden fixtures pin the bytes.
- **D10 (reprint payload degrade)** — an unparseable/missing cached payload
  degrades to doc-no + column-level totals (total_tax/total_gross) with ZERO
  item rows rather than throwing (doc number still verbatim, still exactly
  once); a missing `sales_invoices` table (adapter throw) is an honest
  NOT_CACHED. Partner data in the payload is intentionally NOT printed
  (013/016 POS-receipt parity).
- **D11 (CrashFreeSessions semantics)** — windows key on session START;
  queries PRUNE records outside the queried window (rolling counter, not an
  archive — a later wider query cannot resurrect pruned records; tested);
  `reportCrash` marks the device's latest session; orphan crashes (no
  session) are ignored (pre-telemetry startup crashes are the host's boot
  concern); empty window ⇒ rate null (never a misleading 0).
- **D12 (6th test file)** — `__tests__/bridge.test.ts` added beyond the
  five named files: detectBridge's fail-closed structural validation is
  W2-b's exact dependency and deserves its own pinned suite (19 tests);
  `*.test.ts` naming kept, no split of an existing file.
- **D13 (rollout halt-check order)** — halt (rate < 0.985 ∧ sessions ≥ 50)
  is evaluated FIRST at EVERY stage (a fully-rolled-out bad build still
  halts); below 50 sessions the tiny-sample guard HOLDS instead (reason
  says so honestly); at stage 100 there is no promotion (hold +
  "monitoring only", halt stays armed).
- **D14 (evaluateVersionGate ordering)** — downgrade → up-to-date →
  force-update → update-available, matching the binding client sequence
  (an offered version equal to current is up-to-date even if a minVersion is
  set — a ban cannot be enforced without a newer offering; sane manifests
  always offer ≥ minVersion).

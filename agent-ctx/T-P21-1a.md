## Binding mechanics applied (MASTER-PLAN §3 + DRs)

- **DR-P21-02 dual profile**: `createDesktopStore({path, encryptionKey?,
  profile?: "cipher"|"standard"|"auto"})`. Key set + build reports
  `PRAGMA cipher_version` → `"cipher"` (key applied + verified). Key set but
  stock build → **fail-closed `SqlCipherUnavailableError`** UNLESS
  `profile: "standard"` explicit (the recorded sandbox/CI fallback: every other
  invariant enforced — key lives only in the keychain, secret-scan tests assert
  the key bytes never appear in the raw file or the staging manifest, on the
  initial file AND the recovered file). No key → `"standard"`. `profile:
  "cipher"` without a key → loud error. Empty key → loud error. The test suite
  branches on a live build probe so it is honest on a real SQLCipher build
  (Windows CI) too.
- **WAL + foreign_keys** applied and ASSERTED at open (refuses to continue if
  either pragma does not take). Tests re-assert via `PRAGMA` reads THROUGH the
  adapter.
- **StorageAdapter**: `transaction` = better-sqlite3 `db.transaction` (throw →
  rollback; nested → savepoints), `run/all/get` with param normalization
  (undefined→null, boolean→1/0); bounded prepared-statement cache; closed-store
  guard on every operation; `close()` idempotent; `isOpen` live.
- **Pruning surface**: `listBusinessTables` returns the frozen
  `DESKTOP_BUSINESS_TABLES` allowlist (v1 POS subset + v4 desktop tables) —
  never machinery, never `local_events` (audit trail). `deleteOldestSynced`
  guards: dirty rows never pruned; write-set rows only in server-acked terminal
  statuses (`draft_docs`: MERGED/CANCELLED_LOCAL; `pos_sales`: SYNCED);
  oldest-first (`ORDER BY <lru-col> ASC, rowid ASC`); machinery/audit/unknown/
  injection-shaped table names rejected LOUDLY (allowlist + identifier regex).
- **DR-P21-03 byte-exact**: `tableBytes` = `SELECT sum(pgsize) FROM dbstat
  WHERE name = ?` (verified live: better-sqlite3 12.11.1 ships
  SQLITE_ENABLE_DBSTAT_VTAB); empty/missing tables → 0 (no throw); when dbstat
  is absent the store records `byteMeasurement: "row-approx"` and falls back to
  `countRows × 4096` — `DesktopPruneResult.estimated` says so. `pruneDesktopStore`
  loops measure → delete 50/table LRU batch → byte-exact re-measure; stops
  under budget or reports `stillOverBudget: true` honestly; plain DELETEs,
  cursors/machinery untouched.
- **Migrations**: `applyDesktopMigrations` copies sync-core `applyMigrations`
  semantics exactly (single outer transaction, skip applied, record version +
  min_contract_version + applied_at into the SHARED `schema_migrations`
  table); versions 4 and 5 continue the sync-core numbering; re-runs idempotent
  (v5 seeds are INSERT OR IGNORE — runtime meta values never clobbered, tested).
  v4 column meanings frozen per LOCAL_DATABASE §2 (documented in the header).
  Boot-order guard: refuses when `schema_migrations` is empty (sync-core v1–3
  must run first).
- **§6.4 corruption path**: `integrityCheck` handles BOTH result shapes — the
  pragma returning findings AND the pragma itself throwing
  ("database disk image is malformed" / "file is not a database" — recorded
  probe facts; appended trailing garbage is IGNORED by integrity_check, so the
  drill corrupts a real page). `recoverCorruptStore` stages survivors via a
  separate best-effort connection (read-only first, read-write fallback for
  post-crash WAL recovery), refuses loud (`LocalStoreCorruptError`) when the
  staging file cannot be written — NEVER deletes the outbox without staging;
  deletes file + -wal/-shm; recreates (v1–5); re-imports (INSERT OR IGNORE,
  identifier-validated columns); resets cursors + `cursorCount` checksum +
  maintains `inboxCount` (so the next `recoveryPass` sees a consistent store —
  tested) + clears any stale `quarantined` flag + stamps
  `meta.quarantineRecoveryAt`. Returns the fresh store + full outcome counts.
  The staging manifest is kept on disk.

## Deviations / recorded observations

1. **Result type name**: the prune result is exported as
   `DesktopPruneResult` (shape exactly as mandated: `freedBytes, estimated,
   perTable, iterations` + `stillOverBudget`) — avoids the name clash with
   sync-core's `PruneResult` (`{pruned, budgetBytesApprox}`) when W2
   consolidates `src/index.ts`.
2. **Additive info field**: `DesktopStoreInfo` carries a 4th field
   `byteMeasurement: "dbstat" | "row-approx"` — the honest way
   `pruneDesktopStore` knows whether the measurement was exact without poking
   the raw connection (the mandated 3 fields are unchanged).
3. **dbstat observed PRESENT** on better-sqlite3 12.11.1 (SQLite 3.53.2) —
   `estimated === false` in all budget tests; the row-approx fallback path is
   implemented + documented but not exercisable on this build (honest note,
   DR-P21-03 "W1 verifies" satisfied).
4. **Empty-table tableBytes = 0**: an empty table's allocated root page is
   schema overhead, not cached data — 0 data bytes is its budget contribution
   (dbstat would report 4096 for the bare root page; recorded decision).
5. **`PRAGMA integrity_check` throwing** (malformed image / not-a-database)
   is treated as the not-ok verdict — the throw shape is the common real-world
   corruption signal, verified by probe before designing the API.
6. **`applyDesktopMigrations` boot-order guard**: throws when
   `schema_migrations` has no rows (sync-core v1–3 must run first) — an
   honest loud guard against boot-order mistakes, beyond the mandated spec.

## Binding mechanics applied

1. **Retry chain vs idempotency:** the original UNIQUE `(tenant_id, source_type, source_id)`
   blocked resubmission after a terminal REJECTED. Resolution: the arbiter widened to
   `(…, adapter_id)` (RELATIONSHIPS 1:N per adapter) AND a **partial** unique index over
   live states only — terminal rows never block a retry chain. `tax.store.ts` + the new
   submissions store carry the matching `ON CONFLICT (…) WHERE status IN (…)` arbiter
   (42P10 lesson: partial index ⇒ WHERE clause required in the conflict target).
2. **`resolved_line_id` uuid** (not bigint) — matches the sales line PK shape.
3. **`billing_events.type` `payment.refunded`** — the enum widening the refund flow needs.
4. **Plan-grant SQL follows 0025's array_cat pattern**; edit-after-apply is safe because
   global-setup wipes the data dir every run (fresh DB per run, verified).
5. **Permission-seed tuple format**: unindented `('key', …)` at line start — the drift
   checker's `parseSeedKeys` regex is line-anchored by design (fail-closed parser stays
   untouched; the migration follows the house convention instead).

## DR-P21-07 mechanics (as implemented)

**Manifest schema** (`apps/web/desktop.routes.json`, JSON-schema'd in
`scripts/desktop.routes.schema.json`): `{ $schema, include: string[] (≥1,
lowercase kebab path segments), exclude?: string[] (reserved server surfaces:
["api","middleware"]), notes?: string }`. The shell subset = the Offline
Console (`offline`) + the unlock screen (`unlock`) — online use loads the
deployed web app.

**Stash/restore algorithm** (`desktop-export-prebuild.mjs`, zero deps):
1. ABORT-SAFE PRE-RESTORE — if `.desktop-stash/` exists from a crashed run,
   restore from it FIRST (the stash is the authoritative pre-build copy).
2. Validate the manifest: shape + every `include` route exists as
   `app/[locale]/<route>/page.tsx` (fail loud, ALL missing listed) + no
   include route may shadow the reserved `exclude` names.
3. STASH (same-FS renames, no copies): `app/[locale]` (FULL route tree) →
   `.desktop-stash/app-locale`; `app/api` (BFF catch-all + session routes) →
   `.desktop-stash/app-api`; `middleware.ts` → stash; `next-env.d.ts` → stash
   (defensive).
4. REBUILD the reduced tree: `app/[locale]/layout.tsx` (shared chrome —
   `generateStaticParams` gives the ar/en static export) + a COPY of each
   manifest route dir.
5. SPAWN the wrapped command (everything after `--`; `next` is resolved to
   the workspace binary) with `ERP_TARGET=desktop` in its env → next.config
   switches to `output:"export"` + `distDir:"out-desktop"` + unoptimized
   images (verified empirically: the `/`→`/ar` redirect is conditionally
   omitted in desktop mode — redirects are inert/warned in export mode; the
   shell entry is `tauri.conf.json app.windows[0].url` instead).
6. ALWAYS RESTORE (finally — also on build failure, spawn error, SIGINT/
   SIGTERM): remove the derived tree, move every stashed surface back, delete
   `.desktop-stash/`. No git commands run inside the script; `git status`
   after any run must show zero stash leftovers.

**Exclusions**: everything under `app/[locale]` not in the manifest (the full
business UI), `app/api` (BFF), `middleware.ts` (per-request CSP nonce),
`next-env.d.ts` (stability). `app/globals.css` stays (imported by the layout).

## Decisions + deviations (DR list for the completion report)

- **D1 (frontendDist path)** — the task text said `"../../apps/web/out-desktop"`;
  from `apps/desktop/src-tauri` the correct relative path is
  `"../../web/out-desktop"` (the text's form would resolve to
  `apps/apps/web/…`). `check-desktop-shell` asserts the RESOLUTION equals
  `apps/web/out-desktop`.
- **D2 (tauri-plugin-sql → rusqlite, DR-P21-02)** — the plan names
  "tauri-plugin-sql with the sqlcipher feature"; that crate (2.6.0,
  crates.io) publishes only mysql/postgres/sqlite features and its sqlx
  backend cannot carry a SQLCipher key. The sql glue uses rusqlite 0.41:
  default build = bundled stock SQLite (standard profile); `--features
  sqlcipher` = bundled-sqlcipher-vendored-openssl (cipher profile; the
  Windows CI release build passes it). Fail-closed matrix: key present +
  non-cipher build = loud error, never plaintext.
- **D3 (keyring crate, not tauri-plugin-keyring)** — the community
  tauri-plugin-keyring is a single 0.1.0 release (2024-12, no repository);
  the direct `keyring` crate 4 (Windows Credential Manager) is the production
  choice. Documented in the glue header.
- **D4 (connectivity.onChange is an event, not an invoke)** — the shell PUSHES
  `erp:connectivity` (mirroring the official Tauri event API via
  `transformCallback`/`plugin:event|listen` in the bootstrap); `isOnline` is
  the one command. The parity table + check script encode this exactly.
- **D5 (capability grants)** — `capabilities/default.json` grants only the
  core permissions the injected bridge needs (event system for the
  connectivity listener). The 13 bridge commands are crate-local
  invoke_handler commands (callable from the app's own webview by
  construction); the http/updater plugins are registered for their RUST-side
  APIs (reqwest client / updater runtime) — their JS command surfaces are
  deliberately NOT granted to the webview.
- **D6 (out-desktop vs lint — the one real landmine)** — the shared eslint
  config (`packages/config/eslint/index.mjs`, OUTSIDE 2-c ownership) ignores
  `.next`/`dist` but not `out-desktop`; leaving the built export in the tree
  breaks `pnpm --filter @erp/web lint` + root `pnpm lint` with ~2181 errors
  from generated `_next` chunks (proven: lint green with the dir moved away,
  2181 errors with it present). Resolution: `out-desktop` is treated as a
  TRANSIENT, regenerable artifact (gitignored; regenerated in ~40 s by
  `build:desktop`; `check:desktop-shell` PASSes with the "export not built"
  note; the Windows CI builds it fresh before running the check). The
  durable one-liner (`"**/out-desktop/**"` in packages/config/eslint ignores)
  is flagged for W4 / whoever owns packages/config. I did NOT create an
  `apps/web/eslint.config.mjs` override — that would deviate further from the
  repo's single-root-config convention than the artifact-removal does.
- **D7 (plugin glue sizes)** — keychain 66 lines ✓, print 44 ✓ (+133
  windows_impl, separate file), sql 164 (over the "<100" guidance): the
  DR-P21-02 key-profile matrix + the JSON↔SQLite value mappers the bridge
  seam requires; ALL store logic (migrations/prune/corruption) stays in TS.
- **D8 (Rust compile honesty)** — the crate is compile-gated on Windows CI
  (no rustc in the sandbox). This run fixed the two definite/near-definite
  compile bugs found on review (F1 duplicate `mod`, F2 PWSTR coercion);
  remaining windows-rs 0.62 binding-exact shapes (OpenPrinterW param forms,
  StartDocPrinterW's level-polymorphic pointer) are the CI compile's to catch
  — honest note in the windows_impl.rs header. `check-desktop-shell.ts`
  validates STRUCTURE (config/parity/manifest/export/secrets), never rustc.
- **D9 (bundle+sign in one tauri step)** — the workflow runs
  `cargo tauri build --features sqlcipher` with TAURI_SIGNING_PRIVATE_KEY set
  (bundle nsis+msi + minisign .sig updater artifacts in one invocation)
  instead of a separate signing step; identical artifacts, fewer moving
  parts; the structural test pins the order install → build:desktop →
  check:desktop-shell → cargo → signtool → SBOM → upload → manifest publish.
- **D10 (node pin)** — workflow pins `node-version: 22.12` matching the
  existing ci.yml style; `.nvmrc` says `22.12.0` (same line) — the test
  asserts the 22.12 prefix, not byte equality.
- **D11 (pre-existing depcruise count)** — brief said 8 barrel-cycle errors;

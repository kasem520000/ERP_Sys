## The enroll endpoint contract (W2 consumers — 2-a transport, 2-d specs)

```
POST /api/v1/devices/:id/enroll            PUBLIC (PUBLIC_ROUTES; Idempotency-Key exempt)
Body:  { enrollmentSecret: string }        // z.string().min(20).max(200)
200 →  envelope.data = {
         refreshToken,        // the device's FIRST refresh token (chain root, 30d)
         accessToken,         // fresh 15-min HS256 JWT {sub, deviceId, capabilities?}
         expiresAt,           // ISO — the ACCESS token's 15-min expiry
         refreshTokenExpiresAt // ISO — the refresh token's 30-day window
       }                      // field-for-field the RefreshRotation shape
```

Typed failures (no new error classes — the refresh taxonomy): unknown device →
`DEVICE_NOT_FOUND`; wrong/consumed secret OR no-active-membership →
`DEVICE_REFRESH_INVALID` (message "enrollment secret invalid or already used" /
"the device user has no active membership — credential exchange unavailable");
revoked device → `DEVICE_REVOKED` ("no new tokens are minted after revocation").
Side effects on success (one `withTenant` unit of work): `devices.device_key_hash`
SET NULL (one-time proof consumed), `device_refresh_tokens` chain-root row,
`device.enrolled` audit row (actor = the device's user_id; after = the two
expiries only — never secret material). No rollback-survival catch needed (the
enroll path never revokes anything — unlike the refresh reuse path).

`enrollDeviceWithSecret({ deviceId, enrollmentSecret })` is also exported from
`apps/api/src/modules/sync/application/device-enrollment.ts` for direct service
use; `EnrollmentResult` = the four fields above.

```ts
  enroll: (enrollmentSecret: string) => Promise<{ refreshToken; accessToken; expiresAt; refreshTokenExpiresAt }>,
  keychain: Keychain,
  deviceKeyPair?: { publicKey: string; sign: (nonce: string) => string },
  deviceId: string,

// access token NEVER persisted; deviceKey entry = the PUBLIC half (private key
// stays behind the caller's sign closure — SECURITY §3)

// session.ts
class DesktopSession {
  constructor(opts: { getRefreshToken: () => Promise<string|null>,
                      refresh: (refreshToken: string) => Promise<{ accessToken; expiresAt; refreshTokenExpiresAt }>,
                      clock?: () => number,
                      onRotationFailure?: (failure: RotationFailure) => void })
  current(): string | null;  expiresAt(): number | null
  prime(accessToken: string, expiresAt: string): void   // seed from the enroll result
  silentRefreshIfDue(): Promise<string | null>          // refreshes when now ≥ expiresAt−60s

}
ACCESS_TOKEN_REFRESH_MARGIN_MS = 60_000
RotationFailure = { kind: "ROTATION_FAILED" | "NO_CREDENTIAL"; error: unknown; requiresReEnrollment: true }
// CONTRACT: the `refresh` closure persists the ROTATED refresh token before
// resolving (server tokens are one-time-use); concurrent silentRefreshIfDue
// calls share ONE exchange (the reuse mutex — correctness, not performance).

// unlock.ts
SNAPSHOT_WATERMARK_MS = 7*24*3600*1000
unlockWithSnapshot(adapter: StorageAdapter, opts?: { now?: Date }):
  | { mode: "full"; permissions: string[]; snapshotAt: Date }
  | { mode: "readonly"; reason: "SNAPSHOT_EXPIRED"; snapshotAt: Date }
  | { mode: "readonly"; reason: "NO_SNAPSHOT" }        // strictly > 7d = expired (sync-core parity)
applyPermissionSnapshotRows(adapter, permissions: readonly string[]): void   // atomic key-set swap
applyPermissionSnapshotPayload(adapter, payload: PermissionSnapshotPayload): void
// payload = the permissions-feed change shape { userId, permissions, snapshotAt, watermarkDays }
```

## Decisions (for the completion report's DR ledger)

1. **DR-P21-01 implemented exactly as binding** — PUBLIC route, sha256 vs
   `devices.device_key_hash`, one-time clear, `issueRefreshToken` chain root,
   `device.enrolled` audit, refresh's failure taxonomy (no existence leak),
   no `@RequirePermissions`, `@HttpCode(200)`, header documents that the phase
   doc's "API changes: none" freezes the sync WIRE protocol (pull/push) — this
   credential exchange is the recorded PHASE-020-completion-report exception.
2. **Migration 0032 was REQUIRED by the one-time semantics.** The task says
   "SET device_key_hash = NULL … the DB row's device_key_hash is NULL after
   first success", but 0003 declared the column `NOT NULL` (verified: only
   0003 touches it; pull.spec's fixture comment says "NOT NULL + unique").
   0032 (`ALTER TABLE devices ALTER COLUMN device_key_hash DROP NOT NULL`) is
   backward compatible (every existing writer still provides a hash; the
   unique index treats NULLs as distinct). Four-place manifest consistency
   kept green: SQL file + MIGRATIONS list + journal idx 31 +
   migrations.spec.ts last-tag pin; drizzle `schema.ts` deviceKeyHash made
   nullable to prevent a future `drizzle-kit generate` from re-tightening it.
   Recorded as part of DR-P21-01 (the endpoint cannot ship without it).
3. **Concurrent double-spend closed the rotateRefreshToken way**: the proof is
   consumed by a conditional `UPDATE … WHERE id = $1 AND device_key_hash =
   sha256($secret) RETURNING id` — the hash rides the WHERE clause, so two
   in-flight enrolls with the same secret → exactly one wins, the loser gets
   `DeviceRefreshInvalidError` (0 rows), never a second mint.
4. **AUTHORIZATION_MATRIX format follows the drift-script arbiter.** The
   checker parses ONLY `### 3.x` table rows' first cells for backticked dotted
   keys (permissions-drift.ts §parse rules) — a literal table row carrying
   `POST /api/v1/devices/:id/enroll` inside §3.x would register as an unseeded
   permission key and break the gate. The file's existing format for
   route-level facts is the §3.8 note paragraphs (POS/Distribution/
   Manufacturing/CRM notes), so the enroll route is documented as the "Sync
   credential-exchange note (PHASE-020 → PHASE-021, DR-P21-01)" covering both
   PUBLIC credential routes (refresh + enroll), their no-key-by-design
   rationale, tenant derivation, and the no-leak failure shape.
   `pnpm check:permissions-drift` green: matrix 243 = seed 243.
5. **TENANT_DESKTOP (21212121) is ALREADY USED** (push.spec.ts + policies.spec.ts
   `TENANT_PUSH`) — the master plan's "verify unused before use" fails. The
   enroll DB spec uses a fresh dedicated tenant 41414141 (verified unused)
   keeping the no-cross-file-state convention; ACTOR ids …4101/…4102.
6. **The enroll controller needs no rollback-survival catch** (unlike refresh):
   enrollDeviceWithSecret never revokes anything, so a thrown error rolls back
   its unit of work cleanly — nothing to re-apply post-rollback.
7. **Desktop unlock permission cache (new store contract, recorded for W2)**:
   sync-core's pull applier persists ONLY the `permissionSnapshotAt` watermark
   — the permission KEYS ride the payload but land nowhere. unlock.ts defines
   the desktop cache: a local `permissions` table (`key TEXT PRIMARY KEY`)
   atomically swapped by `applyPermissionSnapshotPayload` (rows + watermark in
   one call — the W2 sync host wires it into the pull applier for
   `permissions` UPSERTs). The reader is fail-soft on a store without the
   table (empty key set; the watermark stays the mode authority — an absent
   cache never blocks unlock, it just grants no affordances).
8. **DesktopSession's refresh closure owns persisting the rotated refresh
   token** (the task's callback shape returns no successor token): documented
   on the seam + exercised by the tests' rotation harness (a session that
   re-presents a consumed token gets the typed reuse error). The in-flight
   mutex serializes exchanges — two concurrent `silentRefreshIfDue()` share
   ONE exchange, because presenting a one-time-use token twice IS the
   M-05 reuse signal.
9. **The deviceKey keychain entry stores the PUBLIC half** — the task's
   deviceKeyPair shape (`{publicKey, sign}`) never exposes private material
   to the module (it stays in the OS keystore behind the sign closure,
   SECURITY §3). The `dbKey` entry is NOT written by enrollment (the store
   bootstrap owns it — enrollment cannot precede store opening).
10. **register/deviceId mismatch aborts before any credential write** — the
    task's input carries `deviceId` (the keychain namespace); a transport
    returning a different id would file credentials under the WRONG namespace:
    fail-loud, never a fallback.

## Deviations from the task text

1. Migration 0032 + its 4 manifest touchpoints (decision 2) — the task's
   "SET device_key_hash = NULL" is impossible against 0003's NOT NULL; the
   task's own instruction to "inspect the actual devices table columns … to
   get REAL column names" flagged the schema as the source of truth.
2. AUTHORIZATION_MATRIX: a note paragraph (the file's existing format for
   route-level facts) instead of a §3.x table row — the drift script is the
   arbiter and a table row would break it (decision 4).
3. DB spec tenant 41414141 instead of TENANT_DESKTOP 21212121 (decision 5).
4. DesktopSession gained `prime()`/`expiresAt()`/`clear()` (small, documented
   accessors the W2 host needs — seeding the enroll-time token avoids a
   redundant immediate refresh); `onRotationFailure` rides the constructor
   opts as the task's "onRotationFailure callback path" requires.
5. unlock.ts additionally exports the two permission-cache writers (decision 7)
   — the reader alone has nothing to read; W2 wires them into the pull applier.

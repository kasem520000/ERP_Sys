## Binding mechanics applied

1. **The gate is the decider, not the coder:** the verification gate (pinned official
   SDK versions + exercised ZATCA sandbox + validated sample invoices + legal review,
   archived evidence) could not be passed in this environment — every item honestly
   NOT_VERIFIED. T4 therefore ships the refusing stub; the completion report marks the
   real adapter INCOMPLETE with the four named unmet items.
2. **`require_tx` via import, not `require`** — the pg-boss job bodies use the ambient
   tenant context through a clean helper (ESM import).
3. **Error surfaces:** UNVERIFIED refusals are typed errors with the gate-item list in
   the details — operators see exactly what is missing, never a silent no-op.

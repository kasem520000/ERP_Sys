## Deviations / recorded observations

1. **Workflow step order vs MASTER-PLAN §10's sketch:** §10 sketched
   "install (root, frozen) → install apps/mobile/native → check:mobile-shell
   → typecheck/lint/test gates → EAS build". The delivered order follows the
   task brief: quality gates → shell → tokens/i18n → native install → EAS.
   Rationale: all pnpm-level gates run before the EAS leg (the native install
   sits immediately before the only step that needs it); the structural test
   asserts the delivered order. Recorded as the operative-spec decision.
2. **The desktop's ≥50-session tiny-sample halt guard is NOT ported:**
   MASTER-PLAN §0 expresses the mobile halt unconditionally
   ("halt < 98.5% ⇒ publish minVersion = last-known-good"); the mobile
   rollout module halts on ANY sub-98.5% rate (rate 0.5 over 5 sessions
   halts — asserted in `rollout.test.ts` with this note). The empty-window
   guard (null rate / 0 sessions → hold) IS ported (a rate of 0 would
   spuriously halt every fresh channel).
3. **`apps/mobile/package.json` `"main": "./native/App.tsx"`** — one field
   beyond the deliverable list: metro resolves the app entry from the
   project-root package.json, and without this the EAS build would bundle the
   library barrel (no UI registration) as the entry. The library surface
   stays on `exports["."] → ./src/index.ts` (unchanged), so no workspace
   consumer follows the entry; asserted by check:mobile-shell §2 + the ci
   test; documented in both READMEs.
4. **`native/package.json` gained `"packageManager": "pnpm@9.15.9"`** — the
   brief's "use the package manager the native package.json implies"
   resolves to this pin (corepack reads it on the runner); the workflow's
   native install (`pnpm install --no-frozen-lockfile`) follows it and the
   gate asserts it matches the root.
5. **EAS build leg is structurally honest, not sandbox-executed:** the step
   runs `eas-cli build --local` from the EAS project root (apps/mobile —
   eas.json/app.config.ts/metro.config.js; entry via deviation 3) on
   ubuntu-latest (Android SDK present); the metro monorepo wiring
   (watchFolders/nodeModulesPaths over the pnpm layout — the seam
   metro.config.js documents) is verified on the FIRST real EAS run. The
   workflow + native/README state this explicitly; the apk/aab upload
   (`if-no-files-found: warn`) plus the `::warning::` lines make a
   secrets-less run honest, never silently green.
6. **The no-inline-secrets test heuristic was refined vs the desktop's:**
   the desktop regex (`[A-Za-z0-9+/]{60,}`) false-positived on the Gradle
   output path (`apps/mobile/native/android/app/build/outputs/bundle/release/`
   — 61 lowercase class-chars). The mobile test now requires mixed case AND
   digits (real base64 material always has both); the desktop test is
   untouched (its file passes as-is).
7. **FCM seam shape:** the workflow materializes the APP-side
   `google-services.json` from `FCM_PROJECT_ID/FCM_APP_ID/FCM_API_KEY`; the
   SERVER-side FCM service-account pair (client email + private key) belongs
   to the API's FCM adapter configuration (task 2-d /
   ENVIRONMENT_CONFIGURATION) — never in the mobile workflow. The eas.json +
   native/README comments say so.
8. **check:mobile-shell §5/§7 grep scope:** "screens import only allowed
   modules" is enforced per file across ALL 15 screen-area files (screens +
   chrome + registry + barrels), not just the 11 components — the registry
   and barrels are part of the screen surface; §7's spot-checks cover the
   same set with comments stripped and `rtl-exempt` honored (the ESLint
   DR-P22-03 rule remains the primary RTL gate — the structural mirror is
   belt-and-braces, printed as such).
